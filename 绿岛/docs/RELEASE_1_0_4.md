# Fire生活 1.0.4（104）发布与验收

此提交更新源码、官网和版本配置，不包含已经签名的 APK，也不会自动部署 CloudBase。

## 改动
- 极简拔草只有进行中、挑战成功、已购买三栏。提前不买或到期后确认没买算成功；到期不会自动完成。下次进入 App 会在首页、工具页或拔草列表询问待确认项目。关闭、返回或稍后再说均不记录购买，同次访问暂缓剩余提醒。
- 列表和详情支持删除，删除前提示不可恢复；保存失败保留原记录。详情按路由 ID 响应账号恢复后的数据，兼容旧数字 ID。旧成功状态保留，旧 failed 状态需要重新确认是否购买。
- 首页切换自由日/我的目标，目标显示完整倒计时。目标详情可以删除，删除后切回自由日并移除对应草稿与任务，不删除资产和自由日计划。
- 今日行动最多三项，按日期轮换。记账5经验（每天1次）；资产8（每月最多2次、跨月也至少间隔14天）；目标8（每自然周1次，有目标才显示）；收藏2（不同他人帖子或官方帖子每天最多3篇，每篇终身1次）；审核通过的发帖10（90天1次）；审核通过的实质编辑8（60天1次，帖子首次发布至少60天）。单次不超过10。编辑正文去除空白后至少改变30字，或更新时间线。社区会员权限保持原有规则。
- 无书籍的阅读任务与性格测试不进入任务池。音乐工具可直接进入，不新增音乐奖励。
- 奖励用独立云端账本，重复保存、取消收藏再收藏、删除重建不重置领取周期。旧经验在首次建立账本时保留。无网先保存操作，联网后确认奖励；不要把“已保存”理解为已发放经验。

## 先部署云函数
1. 更新整个 cloudfunctions/accountData 目录，尤其 service.js 和新增 action-rewards.js，保持原 index.js、package.json 等文件；安装依赖后部署。
2. 创建两个空集合：action_rewards、action_reward_claims。两者都设为仅管理员可直接读写，客户端只通过 accountData 云函数访问。不要开放全部读写权限。
3. 保留原集合与存档，不清空 user_states，不删除已有会员、收藏、资产和帖子。
4. 云函数支持 actions.get，并在资料保存、收藏保存、审核通过时返回权威经验。先部署后发布客户端，避免新 App 请求旧服务报未知操作。

## 打包和官网
1. 拉取源码，保留本机 .env.local 的 CloudBase 移动端授权参数。HBuilderX 打 Android 正式包：versionName=1.0.4、versionCode=104，包名和签名必须与旧版一致。
2. 在 CloudBase 静态托管 lvdao 更新完整站点：download.html 另存为根目录 index.html，上传 fireday-1.0.4.apk，再复制同一安装包为根目录 fireday.apk；app-update.json 也放根目录。
3. 先保持 android.published=false，实际下载 https://fireday.cn/fireday-1.0.4.apk 安装确认版本104，再将 JSON 的 published 改为 true 并上传。没有上传 APK 之前不要开启，以免用户下载到404或旧版。
4. 官网按钮读取已发布 JSON 的链接，失败则保留 ./fireday.apk 可点击下载。iOS 暂无商店链接，仍显示即将上线；无 Windows 入口。
5. 手机保留旧103测试：设置→检查更新→立即更新→浏览器打开 https://fireday.cn/#download →下载104覆盖安装。已有更早版本只有内置检查更新逻辑才会主动提示；单纯提高官网版本号不能给未内置检查器的老包加功能。
6. 关闭或稍后更新不会强制跳转。自动提醒遇到拔草到期弹窗时先显示拔草确认，更新稍后再检查；手动检查仍可用。

## 验收
- 创建拔草项目→列表→详情；旧数字 ID；账号云端恢复后详情能出现。
- 到期项目弹窗选没买/买了分别进入成功/已购买；关闭/稍后不改变状态；多个项目连续确认；删除取消/确认/存储失败。
- 目标发布→首页我的目标秒级倒计时；删除取消与确认；财务/FIRE/经验不变。
- 记账、资产、目标保存后能回到对应页面并更新任务；重复保存不重复经验，资产14天跨月限制，目标每周限制。
- 收藏取消重加无额外经验；同日三篇上限；自己的帖子无收藏奖励；发帖和编辑须审核通过且符合周期。
- 不同账号切换不串用项目和奖励；云端冲突继续保留两份记录，禁止空存档覆盖已有财务资料。
