# 1.0.5（105）：行动任务与经验同步修复

## 原因与改动
- 奖励账户读取后包含数据库系统字段 _id，原代码将其再次传入 set 更新。严格数据库校验会拒绝，导致奖励事务失败。更新时现在剔除 _id，保留账户归属、已有经验和奖励频率。
- 原 state.save 在财务资料提交成功后才发奖励。奖励报错会导致整个接口返回失败，客户端拿不到已经增加的存档 revision，再保存就可能发生无谓冲突。现在成功提交的财务/收藏/审核结果仍返回正确版本，并单独返回 rewardsError。不会把未上传成功的资料标记成云端已保存。
- 奖励失败与财务同步状态分开显示。首页今日行动、英雄页会显示同步提示与重试；旧云函数没有奖励接口时也会提示，避免静默失败。
- 返回首页先等待本机修改上传，再读取奖励回执，并合并同一账号的重复刷新请求。已完成任务优先显示，避免轮换任务池把完成结果藏起来。
- 重新读取时从已保存、仍符合原有时间和频率限制的操作补发奖励；领取记录和累计经验不重置。同一任务反复刷新不重复加经验。

## 部署顺序
1. 保留现有数据库、存档及两个奖励集合，仍为 ADMINONLY，不要删除或重建。
2. 在现有 accountData 云函数中替换最新 action-rewards.js 和 service.js，保留 index.js、package.json、现有环境变量。保存并部署。此次核心发奖修复在云端；运行104的用户重新打开 App 或返回首页后可重试符合条件的奖励。
3. 若更新前已因“资料提交成功但奖励失败”产生 revision 不同，App 原有存档冲突流程仍会保护本机与云端两份资料。先核对差异再采用其中一份，不要清库或卸载。
4. 客户端拉取完整最新源码打包1.0.5（105），包名和签名证书必须与旧 APK 一致。105包含明确提示和重试入口。
5. 官网将 download.html 部署为 index.html，上传 fireday-1.0.5.apk；同一 APK 复制为 fireday.apk 保留直链。上传 app-update.json，确认版本包实际可下载后才把 android.published 改为true。仓库配置默认false，不会提前提醒用户下载不存在的包。

## 检查
运行 node scripts/check-action-reward-sync.mjs，使用带有只读 _id 限制、事务回滚、断网和失败注入的模拟环境验证实际模块。其他回归脚本继续保留。
实际云端环境仍需部署后验证：当日保存一笔支出、符合频率的资产记录、有目标时保存目标，检查任务完成、累计经验和重复刷新。未进行生产写入或签名 APK 真机测试。

若部署后仍报错，提供 App 上的同步提示，以及 accountData 日志中的 [action-rewards] 错误码即可定位；不需要提供验证码、密钥或用户完整财务记录。
