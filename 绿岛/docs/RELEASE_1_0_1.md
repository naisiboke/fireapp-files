# Fire生活 1.0.1 / 101：覆盖与发布说明

## 本次覆盖内容

本次更新在原有邮箱登录、紧凑 AI 聊天、会员兑换和首页加号扇形菜单的基础上继续修改：

- 全部页面共用运行时状态栏高度；标题与状态栏之间保留 12px，固定标题下的内容再留 12px。网页没有状态栏时只保留正常内容间距。背景继续铺满，底部导航和原加号保持原位置。
- 首页日期改为 fireday.cn；未填写财务资料时只显示一句提示和“填写资料”。隐藏常态空存档横幅；实际同步错误仍保留重试入口。
- 资产页和财务表单都记录资产并触发当天选中的资产任务；金额、记录、任务和 EXP 同时落盘。重复提交只补漏记的任务，不重复奖励。历史月份不计当前月份任务。资产页保存成功立即返回首页，本机保存失败保留输入和页面。
- 修正设备日期回调后，未来日期任务缓存不能阻止今天的任务；从已有奖励日志修复完成标记时不重复发放 EXP。
- 原生 App 自动刷新有效登录；明确的 invalid_grant / 无效刷新令牌会先保存账号记录与当前表单草稿，再进入邮箱登录。普通网络错误、超时和权限拒绝不跳登录页。
- 原账号重新登录后保留待同步修改、恢复原页面及输入；换账号不带入旧账号草稿。云端与本机同时修改时继续保留两份，不自动覆盖冲突。
- 增加自动检查更新及“设置 → 检查更新”。提示为可取消的普通更新；确认后通过系统浏览器打开官网 APK，iOS 仅使用配置好的真实 App Store 链接。无静默安装、无 WGT 热更新。
- manifest.json 版本为 1.0.1 / 101，设置底部显示安装版本，便于核对是否已装上修复版。

## 先打包安装 App

1. 从 GitHub main 下载最新项目，覆盖本机项目中的对应源文件；建议完整下载绿岛目录，保留自己的签名证书和本地配置。
2. HBuilderX 打开绿岛项目，确认 manifest.json 为版本名称 1.0.1、版本号 101。
3. 发行 → 原生 App 云打包 → Android → 打正式包。保持已发布 App 的包名和签名证书一致。
4. 在原 App 上覆盖安装，不要卸载，也不要清除应用数据。
5. 之前未包含更新检查逻辑的旧 APK，首次仍需用户从官网手动下载覆盖安装；更新过的用户以后才会收到本功能的提示。

本次修复是客户端更新。仅修改官网 HTML 或重新部署 accountData，不能改变已经安装的旧 APK。

## 在 CloudBase 官网发布更新信息

网站继续使用目前的 CloudBase 静态网站托管应用 lvdao（fireday.cn 对应的应用）。

先准备和上传以下内容，注意是网站根目录里的文件，不额外套一层“官方”文件夹：

```text
index.html                 ← 现有 download.html 作为官网入口
fireday.apk                ← 官网原有安卓按钮对应的安装包
fireday-1.0.1.apk           ← 新的版本专用安装包
app-update.json            ← 仓库根目录的新文件
```

上传 APK 后先直接访问 https://fireday.cn/fireday-1.0.1.apk 验证可下载，再修改 app-update.json：

```json
{
  "appId": "__UNI__6A9B0BE",
  "android": {
    "published": true,
    "versionCode": 101,
    "versionName": "1.0.1",
    "downloadUrl": "https://fireday.cn/fireday-1.0.1.apk",
    "notes": [
      "全页面统一顶部间距，首页更简洁",
      "修复资产任务并在保存后返回首页",
      "登录失效时保留本机记录和输入草稿"
    ]
  },
  "ios": null
}
```

仓库默认 published 为 false，避免在 APK 尚未上传时推送 404 链接。确认能下载后才设为 true 并重新上传 JSON。推荐 JSON 使用 Cache-Control: no-cache；客户端请求也带时间参数。不要覆盖或删除现有官网必需的其他资源。

当前版本 101 看到配置 101 时不会提示，这是正确行为。以后发布 1.0.2 时，App manifest 版本号和 JSON 的 versionCode 都改为 102，先上传 fireday-1.0.2.apk，再更新 JSON。版本号必须递增。仅修改版本名称没有作用。

iOS 上架后才添加 ios 对象，字段同 Android，downloadUrl 填真实的 https://apps.apple.com/... 应用链接。没有上架地址时继续保留 null，不填占位地址。

## 需要在真实 APK 验证

源码逻辑检查不能替代打包和真机测试：

1. Android 普通状态栏、刘海屏、横竖屏切换；检查首页、AI、资产、登录、设置等所有页面不遮挡系统时间。
2. 当前月份记录资产，保存后自动回首页，任务数和 EXP 增加；重复确认金额不重复奖励。填上一月份只保存历史记录。
3. 从财务表单保存资产同样能完成资产任务。若旧记录漏奖，重新确认本月金额一次补记。
4. 让测试账号登录失效，在资产/记账/财务/AI 等页面保留输入后触发同步；应只跳转一次，登录原邮箱后恢复输入和记录。换另一个邮箱不应出现前一用户内容。测试前先通过应用导出数据，不要在正式用户资料上做删除实验。
5. 断网、请求超时、403 时保留页面和记录，不强制退出；联网后重试同步。
6. 使用比安装版本高、且 APK 已可下载的测试版本配置验证更新提示；取消能继续使用，手动检查仍可再次打开。测试完成恢复正式版本配置。
