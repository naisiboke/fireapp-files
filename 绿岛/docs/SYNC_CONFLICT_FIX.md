# 1.0.2 / 102：存档版本冲突不再阻止登录

## 截图里的提示是什么意思

旧版使用本机保存的云端版本号与服务端当前版本号比较。两者不同且本机还有待同步修改时，恢复流程直接返回失败，邮箱验证码即使验证成功，用户也留在登录页。

这只能证明两份存档的版本不同，不能确定确实有另一台设备。另一设备写入、网页写入，或上传成功但客户端未收到确认等情况都可能产生版本差异。

## 修复后的流程

- 邮箱验证成功与资料冲突分开处理。遇到冲突后保留本机可用记录，进入“选择同步版本”，也可以直接“先进入 App，稍后处理”。
- 已验证邮箱但恢复暂未完成时，可点“已验证邮箱，继续进入”，不反复申请验证码；真实登录失效仍走原来的邮箱重新验证流程。
- 页面并列显示本机与云端的资产、记账、资产记录、消费计划、AI 对话和性格报告数量。
- 用户明确选“采用云端版本”后才替换当前本机资料；明确选“采用本机版本”后才用当前云端版本号提交。
- 切换前将两份完整状态单独备份到当前账号的本机命名空间。备份失败或当前缓存写入失败时不切换；不会静默合并、清空或把 A 账号资料转给 B 账号。
- 原存档备份按 ID 单独保留，不随下一次冲突覆盖。冲突页可主动复制备份 JSON 保存。备份在本机，卸载应用会丢失本机备份。
- 处理期间云端又变化或本机新增修改时，要求重新核对。网络失败保留原版本；账号切换立即取消旧操作。仅对象字段顺序不同不会再被标记为本机新增修改。
- 首页同步提示和设置里的“云端同步”均可重新进入选择页面。稍后处理期间暂停有冲突的财务存档上传，仍可保存本机记录。

这是完整版本切换，不会自动把两份记账或聊天历史拼接。切换确认中会说明哪一份成为当前版本；另一份保留备份。

## 发布

1. 下载 GitHub main 最新绿岛源代码，版本名称为 1.0.2、版本号 102。
2. 使用已发布 App 相同的 Android 包名和签名证书打正式包，覆盖安装；不卸载、不清除数据。
3. 本次不需要修改或重新部署 accountData 云函数。
4. 若通过官网提示更新，先上传新 APK 到静态网站根目录，确保 https://fireday.cn/fireday-1.0.2.apk 可下载，再上传 app-update.json 并将 android.published 改为 true。仓库里的默认值仍是 false，避免下载链接 404。官网原按钮使用的 fireday.apk 同时换成新包。
5. 检查设置显示 1.0.2。旧 APK 内的代码不会因更新官网文件自动改变。

## 验证

运行 scripts/check-account-data.mjs，覆盖真实存储/客户端/后端模块和登录、选择页面脚本的隔离场景：允许本机模式进入、两份备份、采用任一版本、稍后处理、取消、备份失败、缓存失败、网络失败、处理中远端更新、未保存的新本机修改、账号切换和无需重复验证码。

并回归 check-release-recovery.mjs、check-asset-task.mjs、check-cloudbase-platform.mjs、check-ai-profile-privacy.mjs、check-ledger-summary.mjs、check-vip-redemption.mjs。

隔离检查不访问生产资料，也不能替代 HBuilderX 构建及真实 APK 验收。请在安装 1.0.2 的设备上确认：验证邮箱后能进入选择页面，先进入 App 可看到本机记录，稍后从首页处理同步，选择云端/本机前弹出确认，版本切换后同步恢复。
