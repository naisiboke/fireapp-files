# 三天 VIP 兑换与 AI 聊天布局修复

## 必须更新现有 accountData 云函数

前端旧兑换按钮没有调用云端，只提示“服务迁移中”。本次补上真正的兑换与会员查询。
只打 APK 不会部署新接口。

1. 保留所有现有数据库记录。
2. 在 CloudBase 的普通云函数 accountData 中，用仓库 `cloudfunctions/accountData/service.js` 的最新文件替换旧 service.js，再部署。
   index.js、package.json 入口及 Node.js 环境无需更换。本次没有新增依赖。
3. 确认现有 vip_codes 集合存在，客户端权限设为“无权限 ADMINONLY”，兑换由已登录云函数处理。
4. 每条码的格式：

```json
{
  "code": "FIRE3D-示例-随机字符",
  "durationDays": 3,
  "status": "unused",
  "usedAt": ""
}
```

示例 code 仅说明字段，实际码使用你原先生成的值。不要重新生成或删除现有码。
App 输入的是 `code` 字段的完整值，不能填自动生成的 `_id`。
支持忽略首尾空格、大小写，并兼容粘贴时的长横线。
如需创建唯一索引，字段为 `code` 升序、唯一；先核实没有重复，服务本身也会拒绝重复配置的码。

5. 更新客户端源码，在“绿岛”执行 npm install，重新打包并使用原证书覆盖安装。

## 服务端行为

- 只能由已登录用户兑换；忽略外部传入的 UID。
- 在同一事务里确认未使用、写入会员期限并标记兑换码使用者。每码仅一个账号使用。
- durationDays=3 是从服务端时间起 72 小时；已有未过期会员在原到期时间上延长。
- 同账号重复提交同一码只刷新状态，防止响应丢失后重复增加天数。
- 无期限会员不消耗兑换码，失效码和非法天数不会被消耗。
- 每个账号十分钟最多十次格式有效的兑换请求；不用解除数据库权限。
- 会员状态保存在 user_states 的受保护 membership 字段；有财务 state 时同步带入 state.membership。
- 兑换不修改财务修订号、不清空财务。普通状态上传不能伪造、延长或取消云端会员。
- 仅兑换过会员但尚无财务档案的账号，bootstrap 仍返回 exists=false、state=null，并单独返回 membership。
- 保留已核实 UID 的旧财务迁移和 data_backups 备份。
- 设置页、会员页与 AI 页重新显示时刷新服务器状态；兑换成功立即更新当前账号。
- 这里修复会员兑换/读取与客户端会员展示。原有 AI / 支付 HTTP 服务仍保持原接口，本次未更改它们的服务端计费实现。

## AI 页

顶部改成一行小导航：我的性格、剩余免费次数/会员状态、历史。
移除重复的大块说明；“结合我的情况给建议”缩成输入栏旁的“建议”按钮。
聊天区域和输入栏在同一弹性布局中，不再用固定输入栏加 120px 留白叠在一起。
为键盘弹出与窗口缩放计算可见高度；隐藏键盘后恢复。长回答保留原文和换行，不截到 6 句或 420 字。

## 真机验收

- 输入 code，不是 _id：提示兑换 3 天，显示真实到期日期，重新打开与另一设备登录仍可读。
- 快速点击、断网后重试同一码：不重复延长；另一账号兑换同一码被拒绝。
- 保存财务、重新登录：会员期限不丢失，财务不被重置。
- 会员过期后恢复非会员状态；原手机号/第三方账号不会被删除或自动合并。
- 查看长 AI 回复，滚动到顶部与末尾；打开键盘和收起键盘后消息、输入框不互相遮挡。

本次使用隔离测试验证事务、期限、重试、账号归属和布局相关交互；不能替代实际云端部署与 APK 真机验收。
