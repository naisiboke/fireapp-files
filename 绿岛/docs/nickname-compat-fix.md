Fire生活 · 昵称正则兼容修复
日期：2026-11-08

报错原因
上一版在 App 的 utils/nickname.js 和 accountData 云函数的 service.js 中使用了 Unicode 属性转义 \p{Script=Han}。
当前运行环境不接受该写法，会抛出 Invalid regular expression / Invalid property name，可能中断账号恢复或昵称相关流程。

本次修复
两处同时改为按字符码点检查中文、字母和数字，不再使用 Unicode 属性转义正则。保持2–8字符、常见攻击变体拦截和云端严格AI审核。
昵称与社区投稿仍各自审核；AI聊天继续每条只调用一次模型、max_tokens=500，没有新增聊天复审或自动续写。
兼容检查覆盖常用简体/繁体汉字、较少见的汉字、英文数字、8字符边界、隐形字符、表情、孤立代理项和攻击性表达。前后端规则一致。
旧语法解析检查使用 ECMAScript 2017 模式，确认旧写法会被拒绝、新校验代码能通过；登录恢复回归改为使用真实昵称校验函数。

更新顺序
1. 先备份现有 accountData 源码。
2. 将包内 cloudfunctions/accountData/service.js 覆盖到当前 accountData 云函数根目录，点击部署，等待成功。
   保留现有 index.js、action-rewards.js、recover-legacy.js、package.json、依赖和已有环境变量。
3. 将包内“绿岛”同名文件覆盖 App 工程。核心修复文件为 utils/nickname.js。
4. 使用原包名和原签名证书重新打包，覆盖安装后重试“已验证邮箱，继续进入”或邮箱验证码登录。
   这次修复无需删除云端资料、清空本机记录或更换证书。仅更新云函数不能替换手机内已有的昵称校验代码。
5. 本包是累计源码覆盖包，包含此前相关更新；不是已签名APK。包名、证书和版本提示文件保持原工程配置。

检查
- 不再出现截图中的正则错误。
- 已验证邮箱继续进入后能恢复原账户记录；昵称可填写并送审。
- 中文、英文数字昵称按同样的2–8字符规则处理，表情和隐形字符仍不能绕过限制。
- AI聊天仍只有一次模型调用，500为输出token上限；昵称与社区审核保留。
- 自动验证不读取生产账户、不调用真实AI计费接口。H5编译与浏览器检查不能替代最终Android设备验收。
