# 问 AI 连续出现 AI_BUSY 的修复（2026-11-16）

现象：第一条问题得到回答后，后续问题不断提示“上一次回答仍在处理中”。

代码问题：settleAI 使用 aiQuota 的嵌套更新保存日期和次数，却省略 pending。CloudBase 合并更新嵌套对象时，省略字段会保留旧值，已结束请求的预留标记因而可能一直保留到两分钟超时。现在成功和失败结算都明确写入 pending:null；仍在处理的请求继续防重复，过期旧请求不能清除新的预留。

本次只修改 accountData/service.js 的结算和部署标记；未改 App 页面、财务数据、账号、昵称/社区审核、免费额度、会员权益或模型调用预算。每次发送仍只调用一次模型，max_tokens 仍为 500。

## 部署
1. 下载 updates/fire-ai-busy-fix-20261116.zip，解压。
2. 打开其中 cloudfunctions/accountData 文件夹。将里面的五个文件放到腾讯云当前环境 accountData 云函数的代码根目录，覆盖同名文件。不要再多套一层 accountData 文件夹。
3. 保留原有环境变量和密钥，使用当前正常运行的 Node 环境，保存并部署（包含依赖）。无需重新打包 App。
4. 云函数控制台测试输入 {"action":"service.info"}。正确部署后返回 serviceBuild 为 2026-11-16-ai-quota-release-1。
5. 在原 App 连续发送两个问题：第一条回答结束后立即发送第二条，第二条应正常回答。若账户已有旧版预留，最长等两分钟让旧预留过期后再测；无需清空数据库或重置次数。

## 验证
新增 28 项回归检查采用 CloudBase 式嵌套合并更新，已直接复现修复前的未释放标记，并验证修复后连续回答、生成失败立即重试、空返回、真实并发拦截、过期旧响应、新一天额度、会员与账号隔离。完整 Node 回归和更新包一致性检查由 GitHub Actions 执行。
